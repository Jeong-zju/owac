## B0 建设范围与顺序

| 顺序 | 工作 | 交付与边界 |
| --- | --- | --- |
| 1 | 可复现环境与检查入口 | 延续 Python、uv、Ruff 和 pytest；RAW 数值及合成夹具使用 NumPy，版本写入锁文件。采用 JSON 配置与 JSONL 小型清单，先实现类型校验和完整解析配置保存。核心协议不要求 NumPy、特定张量框架或设备。 |
| 2 | 最小数据契约 | 定义整数 RAW 采样、CFA 与实际采样坐标、位深、黑白电平、曝光/增益、时间戳及其时钟、来源和处理历史；分别表达缺失、坏点和饱和。校准保留整数源数据并在 FP32 中执行。实现清单、校验和以及按会话/物体/场景/照明/传感器分组的拆分审计，禁止同一隔离组跨拆分。 |
| 3 | 最小外部接口与状态约定 | 实现 observations、metadata、optional_state、compute_budget 到 representation、optional_state、validity、cost_record 的最小协议。候选负责自身表示、调度及停止；共享工具记录预算与实际消耗，声明可执行的限制，不能把软时间目标称为硬实时保证。状态定义初始化、reset、释放、episode 边界与因果输入条件。 |
| 4 | 可追溯运行入口 | 一个 CPU 本地命令串起配置、数据、接口、读出与记录。保存代码 SHA、dirty diff 与相关未跟踪源码快照、锁文件/环境、数据清单及生成器版本、种子、完整配置、开始/结束时间、退出状态和失败原因。输出写入被忽略的 `outputs/<run-id>/`，研究记录引用可定位的产物及校验值。 |
| 5 | 成本记录与兼容性验收 | 记录输入适配、核心、状态维护、读出及端到端耗时，并说明 I/O、预热和统计范围；无法测量的内存、通信等字段写未测量。以两种不同原生表示的工程探针，以及一个持续状态场景验证接口；相关数值、边界和复现测试纳入检查。 |

配置入口保持显式：运行配置选择实现与数据，不通过动态执行配置代码加载候选。共享执行工具调用候选的执行入口；增量、异步和自定义求解器可以在入口内部实现自己的调度。

真实相机字段不从默认值猜测；合成数据显式标记来源和生成参数。RAW 契约只约束 RAW 输入适配器；另提供一维测量夹具，检查核心接口没有硬编码 Bayer 或二维图像结构。

## 兼容性验收方法

接口先保持实验性，完成下面的工程验证后确定 B0 所需的最小字段与职责：

- 无状态工程探针返回保留坐标的测量场；另一探针返回变长测量集合及独立有效性信息。共享执行与读出流程能消费两者，输出不必转换成同形张量或 token。
- 持续状态探针按时间顺序消费观测；验证新 episode 清空状态、重复运行可复现、相邻 episode 不串状态，以及未来观测不影响先前输出。探针使用已知简单计算规则，只提供软件契约证据，不登记为新的 F 系列框架。
- RAW 夹具覆盖高位深整数、不同 CFA/裁剪原点、黑白电平、缺失/坏点/饱和及非法元数据；验证加载保存无损、校准精度和源数据未被原地覆盖。
- 拆分审计检出预设的分组泄漏；非法配置明确失败；预算到达和求解失败具有明确输出/终止语义；失败运行也保留可追溯记录。
- 干净 checkout 上运行 `uv sync --locked`、`make check`、`uv run --locked pytest` 和完整 smoke 命令。相同版本/配置/数据/种子产生相同语义输出；运行时间等资源测量允许变化，比较时排除这些字段。

两种表示与状态探针通过只能证明这些样例与工程契约兼容。F01—F12 的真实兼容性在各自原型接入时持续复核，不宣称十二个框架已经验证。

## 留给候选与系统研究的工作

完整候选卡、最近方法文献审计、机制任务与评价指标、C0—C4 实现、实际 VLM/VLA、GPU 训练、相机 SDK 和机器人平台由后续研究任务引入。共享底座不要求候选具有同一网络基类、层数、状态结构、内部 token、训练循环或单一评分。

B0 提供分离的输入适配、候选和读出边界，并可用轻量测试读出验证连通性；具体后端的维度、位置编码、mask 和可训练参数协议，在实际后端选定和审计后实现。CPU smoke 不代表真实 RAW、语义对齐或机器人闭环已完成。

## 本地 Git 冻结与分支规则

1. B0 实现使用 `codex/b0-common-baseline` 分支，从本次建设方案提交后的 `main` 创建；按环境、数据、接口、运行记录和验收做可审查的小提交。
2. 验收通过并记录实际命令、结果和限制后，将 B0 合入本地 `main`，在该提交创建注释标签 `owac-dev-v0.1.0`。记录完整 SHA；标签不可移动，当前不得提前创建。
3. F01—F12 的首批开发分支统一从 `owac-dev-v0.1.0` 创建，命名 `codex/f01-<task>` 至 `codex/f12-<task>`。worktree 统一位于 `/home/jeong/zeno/owac/worktrees/<task>/`；每个 checkout 独立安装环境并运行检查。
4. 各候选记录初始基线标签和 SHA。后续子任务可从本家族已有分支继续，保留共同祖先；不在每次任务中重置已有研究。
5. 公共工具的修复通过独立共享变更验证、合入 `main` 并产生新的版本标签；候选显式合并所需更新并记录版本变化。默认不重写已有候选历史，也不静默移动旧标签。

冻结后创建候选 checkout 的示例（在标签存在前不执行）：

```bash
cd /home/jeong/zeno/owac/repo
git worktree add -b codex/f01-mechanism ../worktrees/f01-mechanism owac-dev-v0.1.0
cd ../worktrees/f01-mechanism
uv sync --locked
make check
uv run --locked pytest
```

本地提交、合并和标签用于确定共同起点；远端推送与发布按用户授权执行。B0 冻结与之后的论文证据冻结分别管理。
