**现在实际执行 v1.1 P5：根据完整模型与冻结结果的真实限制，选择一项有意义的迁移/扩展并完成训练、比较和可视化。** 不是把所有方向再串成长期清单，也不在这里补交P3缺少的主体编码器/行动链路。

### 第一步 用实际结果选择扩展

先读P3/P4实际报告、独立验收、失败案例、训练配置、已有原生RAW数据和服务器状态。在 `research/experiments/n01_v1_1/P5_scope.md` 写清一个主要问题、已有证据、最近对照、选择的扩展、数据、训练预算和想证伪的结论。没有理由同时开展四条路线时只做一条。沿用前端专家和监控页，展示所选扩展及当前活动，不把尚未选择的方向全部列成“必须完成”。

默认优先级：

| 实际主要限制 | 优先扩展 | 怎样算回答了问题 |
| --- | --- | --- |
| 主要证据仍只有pseudo-RAW、没有传感器泛化 | A 真实CFA/跨会话或跨传感器；当前默认首选 | 明确输入身份，比较零样本/适配及场景或传感器留出；结论限数据可支持的任务 |
| 增量可能只绑定DBSR结构，成熟替代可运行 | B 第二成熟骨干 | 在有无N01支持修订的同骨干匹配训练下比较 |
| 表征声称可复用但只有π0.5一个读出 | C 第二下游读出 | 共享编码器、合法标签和公平适配，检验表示迁移 |
| 完整模型确有32帧成本/长期依赖瓶颈 | D 长记忆或局部计算 | 完整任务质量与总成本曲线，重新说明删除范围 |

若P4给出与默认不同的明确限制，可选更有依据的一项并直接推进，说明选择，不为常规研究分支反复索取许可。若缺少合法数据/访问授权，先盘点现有公开/已部署资产与可用候选，给具体缺口；不能自行假造数据或购买。真实数据无法取得时，有依据可改B/C；不得用随机马赛克替代A后宣称CFA迁移成功。

### A 真实CFA及跨域迁移

优先参考前文作者代码中的RViDeformer/ReCRVD、RViDeNet/CRVD和AIM2025 RAW视频数据。先读数据README/许可证/原始split和实际文件，记录传感器、bitdepth、CFA相位、黑白电平、曝光增益、时间戳、场景/会话与处理历史。ReCRVD显示屏重拍的性质保留；视频恢复数据不能冒充有机器人动作标签。

1. 有现成真实机器人RAW/动作对齐数据且获授权时，使用真实测量与同步行动评估；没有则先完成原生RAW结构/时序与迁移诊断，明确没有动作闭环能力结论。不在此提示词授权下驱动实体机器人或采集私人数据。
2. 独立 `bayer_cfa` 输入适配，按真实相位/采样坐标与metadata pack，复用已有4/8通道SEA-RAFT和完整内容编码。三通道pseudo-RAW权重迁入四相位stem属于真实适配，登记初始化策略与未匹配参数，不伪装完全兼容，也不因为有一层shape不同就丢掉全部可复用权重。
3. 以场景/会话/传感器为单位划分，动态视频相邻窗口不跨区。只有数据确有多传感器时才称跨传感器；单传感器数据可做跨场景/会话。优先继承作者官方split，新的留出另记版本，不把ISO变化叫新传感器。
4. 至少区分零样本迁移、有限校准/适配、匹配完整fine-tuning。每个比较的适配数据量、参数范围、预算和初始化相同，N/B0/B1的主链/读出公平。核心可训练对照仅用1个训练种子，默认101，与当前P3一致；先测真实速度再排期，不自动扩成三种子。
5. 能取得合法RAW目标/独立噪声样本时，可在RAW域训练成熟内容/运动/支持；Noise2Noise/Noise2Self等要求的噪声与遮蔽假设必须成立。没有这些条件就使用合法任务监督或有边界诊断，不把同一噪声输入复制成目标当去噪成功。RGB监督/教师不进入主链。
6. 恢复任务中的RAW误差、结构/轨迹一致性、删源影响是扩展诊断，不能取代行动结论。若需要为第二读出用RAW目标，保留非图像编码主输出，诊断头独立，不把恢复RGB再喂π0.5。显示同一固定tone mapping、相同帧/色标、真实噪声/支持/对齐与失败例。

先检查数据访问和真实shape/吞吐，建立完整训练配置，再登记适配预算并训练到有可比较的完整曲线。原动作任务30k—100k规划不能机械照搬到小视频数据；参考所选作者训练配方和数据覆盖，报告真实更新、采样场景数、验证曲线及延长理由。去掉作者RGB头和改任务后不能照抄其原步数宣布充分。

### B 第二成熟骨干

优先完整BSRT-L特征/对齐/融合或Burstormer成熟模块，读取前面的逐文件导航。BSRT保留作者规模来源；其Debayer3x3、SpyNet RGB处理、自动下载和本机路径必须合法替换。Burstormer采用前固定真实commit和许可证。只移植几个卷积后命名“BSRT-L”不允许；若显存不足，先做相机/时间分块、梯度checkpointing、batch累积，确需缩规模时如实改名并说明容量，不冒充成熟强骨干。

比较 `新骨干+B0成熟融合`、`新骨干+B1标准检测/reset`、`新骨干+N01支持修订`；与原DBSR三臂形成可解释参照。使用同一真实RawVLA清单、后端、输入、训练机会和开发案例，各核心方法仅1个训练种子；不据此主张训练种子稳定性。训练协议从P3复用而非重新使用旧20步训练器。冻结干预与匹配重训分开；第二骨干结果只支持实际测过的架构范围，不要求顺便重跑所有P4全量。若要对第二骨干给正式全量结论，另建清单/版本与预算，并披露正式测试已消费。

### C 第二下游读出

先选现有合法标签和明确任务，例如真实RawVLA短时动作/控制量预测，或有真实标注的局部结构/时序任务；不凭空生成抓取坐标、深度或几何真值。小型冻结线性probe是评价工具，可以小；不能用小probe替代主体编码器。需要非线性强读出时用来源明确的成熟模块，Perceiver IO只作可选参考，不强制引入Haiku/JAX新栈。

分别比较冻结编码器+同一probe，以及相同数据/预算的公平fine-tuning。第一读出为P3的π0.5，第二读出不复用其测试标签训练；按源轨迹/场景留出。报告迁移相对B0/B1如何变化及第一读出是否遗忘，不用任意probe loss下降宣布泛化架构已成立。真实动作通路的干预仍固定采样随机性。

### D 长记忆或局部计算

先给P3/P4真实profile：时间花在RAW编码、flow、支持、重算还是π0.5；只有瓶颈对应才做优化。默认完整窗口重放是独立正确性参照，不为加速删除它。局部重算必须覆盖实际感受野与flow/参考/归一化依赖，对比完整重算的输出与动作质量，允许合理数值容差，不设跨机器逐位哈希门槛。

如扩展32帧外递归/压缩状态，记录真正保留什么、哪些旧来源还能删除、哪些只能近似遗忘。不能从一个均值/SSM状态宣称恢复任意历史源贡献；Mamba的卷积和SSM缓存都重放或明确限制删除范围。用作者完整模块和成熟配置，先验证合法因果帧，不手搓四层tinyMamba当扩展完成。

用相同真实任务展示质量—时延—内存曲线。总成本包含选择/索引/缓存维护/数据搬运；门控稀疏率不是加速。优化没有收益也报告，不先设“p95必须快5%”之类任意准入线；算法若近似则说明质量和删除保证的变化，不能只报速度。

### 理论与可视化延续

继承P3的G1删除依赖、G2噪声与陈旧偏差、G3顺序证据适用范围。换传感器会改变噪声/曝光假设，换骨干会改变感受野依赖，长记忆会改变删除范围；只对确实改变的部分更新论证与真实反例，不重复搭一个“定理PASS”测试系统。未证明的性质单列，不用实验热图代替证明。

每个所选扩展都交付原画面上的同步热图/支持/对应/来源干预与失败例，沿用P3固定案例和新增域的分层随机案例。网页显示当前数据域、传感器或骨干、零样本/适配/fine-tuning阶段、训练覆盖和原始指标，不新增“域泛化综合分”。
