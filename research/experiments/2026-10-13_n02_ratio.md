# N02 · 独立 NRE／BNRE 测量评分对照

## 运行前协议

依据用户要求，先验证直接学习测量证据能否改善线索互换、无信息校准和 95% 错误先验
纠正；通过后才进入相同评分器下标准滤波与 N02 的局部修订对比。本轮不提交 Git。
基础提交为 `a59f6f2`，实验代码与本记录保留为工作区修改，运行时保存源码快照和哈希。

### 可复用部分与接口

- 从 LAMPE `cbf500c09c538a014e72477d166acc62a6d8409a` 引入原版 `NRELoss`、
  `BNRELoss`，合并导入并按本库格式排版，类 AST 保持一致，完整 MIT 声明随源码保留。
  不安装已停止开发的完整 LAMPE，也不把这称为 sbi 的整库性能复现。
- 每个种子使用此前 tiny-contracts 第 200 步模型的同一个冻结 RAW stem。两个方法
  共用该 stem、评分头初始化和训练采样顺序。RAW 为同一生成器的三通道 pseudo-RAW，
  64×64，八帧；沿用生产的 16×16 测量池化，所有像素有效，无隐藏 cue mask 输入。
- 新头保留空间位置：1×1 卷积 32→4，flatten/linear 1024→32，GRU32，再用共享
  MLP 将前缀状态与候选坐标合成一个 log-ratio。候选固定为 opening-left/right
  的物理二元解释 ±1；不读取真实标签、先验、场景参数、测量模板或未来帧。
  这是已知候选集合下的独立证据诊断，不代表学出了 N02 的候选几何。
- GRU 每序列清零。它直接对整个因果观测前缀评分：`posterior=softmax(log prior+s_t)`。
  更新时替换前缀证据，不累加 `s_1+...+s_t`，避免把相关背景和旧帧重复当独立观测。
  状态压缩历史，不缓存无限 RAW；此结构与原 N02 的循环状态不同，记录参数和成本。
- ratio 只用于全帧候选比较，不构造局部残差图，不代替绝对拟合检查。生产核心、
  `semantic_map` 和最佳候选残差检查保持原样，第一阶段不接入局部撤回。

### 数据与优化预算

- 训练为 train split 的 256 条独立静态 episode，种子 16000–16255，均为
  opening_direction，生成器默认 80% 可辨识概率、noise_sigma=0.01。无场景变化，
  不以本轮结果声称 stale 恢复成立。训练标签仅为真实二元参数。
- 每批独立无放回抽取 16 条 episode。上游损失沿 episode 轴滚动参数构造边缘乘积
  配对，允许负配对恰好同类；不强制错类，也不沿同一序列的帧轴构造负样本。
  每个因果前缀都进入损失均值，时序样本不被当作独立 episode 数量。
- 三个种子 × 两方法 × 200 次新头更新，共 1200 次；BNRE λ=100，采用上游默认值。
  AdamW lr=3e-4、weight_decay=0.01、clip=1；CPU FP32、单线程、确定性算法。
  保存 0/100/200 步；不调 λ、学习率、温度或分数偏置，不按开发结果额外续训。
- 新头初始化为 17000+种子；共享 sampler_seed=17000。两个方法同输入同更新预算。
  相对旧完整模型 B2×T8，本轮为 B16×T8、冻结 stem 的头部训练，不能声称旧模型同算力
  或从零同数据预算的性能优势。冻结 stem 已有的 200 步预训练一并披露。
- 开发为 validation seeds 18000–18015；全部训练结束并写出开发结果后，才生成并
  评估一次新留出 seeds 19000–19015。两者使用相同 validation 几何集合，只是新种子，
  不称第三种未知几何分布。每种子生成同一背景/同一噪声的两线索世界，以及无 cue 世界。
- 精确模板 oracle 与零证据是评估参考。模板只用于已知物理上限、识别真正无线索的
  前缀，不传给评分器或训练损失。保留每条 RAW、特征、源检查点及采样清单哈希。

### 进入第二阶段的条件

每个模型分别在开发与留出满足：

1. 16 对线索互换至少 12 对两侧都选对，严格比较，平分不计正确。
2. 至少 12/16 条无 cue 序列在**所有前缀**、初始 p1 为 0.05/0.5/0.95 时，
   后验相对初始先验偏移均≤0.15；同时报告 log Bayes factor 均值/p95，不只看总体均值。
3. 对每个世界方向分别至少 4/16 条纠正 95% 错误先验：最后一个物理无线索前缀
   的真类质量≤0.25，末帧真类质量≥0.7。不同于把初始先验统一重置为 0.5。

同一方法须在开发和留出均至少 2/3 种子满足所有条件，且三个种子的线索配对、无信息
保持、两方向纠错总通过数从 100 到 200 不下降；有限值、输入隔离与因果检查须通过。
这些门槛沿用此前配对诊断及行为门槛，新增偏置先验的保持检查。通过才推进共用评分器
对比；失败时停止本轮，不延长至 800，不把分类 loss 降低当作行为成立。

## 实际结果

六组正式训练均完成，每组 200 次新头更新；开发和新留出的合格种子数均为 **0/3**。
第一阶段不通过，因此本轮不进入共用评分器的标准滤波／N02 比较，不延长训练。

以下均为新留出结果，按初始化种子 0/1/2 列示，每种子各 16 个场景：

| 指标 | NRE | BNRE |
| --- | --- | --- |
| 线索互换两侧都选对（/16） | 0 / 0 / 0 | 0 / 0 / 0 |
| 无 cue 全前缀保持三种声明先验（/16） | 16 / 16 / 16 | 16 / 16 / 16 |
| 95% 错先验纠正，世界 0（/16） | 0 / 0 / 0 | 0 / 0 / 0 |
| 95% 错先验纠正，世界 1（/16） | 0 / 0 / 0 | 0 / 0 / 0 |
| 无 cue 平均绝对 log BF | 0.00417 / 0.00175 / 0.00562 | 0.00765 / 0.00083 / 0.02078 |
| 交换线索后分数变化方向正确（/16，追加描述指标） | 0 / 3 / 5 | 0 / 7 / 4 |

开发集的通过计数与上表前三类行为相同，100→200 步也没有计数改善；每方法三种子
通过数之和均为 48→48，全部来自无 cue 条件。**初始未训练的新头也已经全部通过无 cue
保持**；最终零证据参考同样为 16/16。因此，不能把这一项解释成训练带来的机制收益。

精确模板 oracle 在开发与留出都达到：配对 16/16、无 cue 16/16、两个纠错方向各
16/16。它使用已知渲染模板和噪声，是有额外信息的物理参考，不能作为可部署学习模型。
其结果证明这些实际输入具备判别信息；不证明冻结 stem 或所选评分头已经能提取该信息。

### 学到的是接近零的证据，尚非可靠判别

NRE 的末训练 loss 为 0.69315 / 0.69299 / 0.69315；BNRE 为 0.69329 / 0.69315 /
0.69321，均接近不区分联合配对与边缘配对的 `log(2)`。原始 loss 数值还包括不同的
BNRE 平衡惩罚，不能直接用于方法排名。训练集末帧类别准确率分别为
48.83% / 52.34% / 51.17% 与 51.17% / 51.17% / 48.83%；训练集标签数为 131:125。
这些指标不支持“训练已经学会，只是泛化稍差”的解释。

新留出有线索世界的末帧绝对 log BF 最大值，六个模型都不超过 0.01969；将 95% 错误
先验提升到真类质量 0.7 需要约 3.79174 的正确方向 log BF。线索交换引起的分数变化
方向也不稳定，因而目前不能只归因为证据尺度或温度。

冻结 stem 的同场景两世界特征差异 RMS 分别为 0.001485 / 0.004184 / 0.002376，
没有逐位相同。该检查只排除了“交换线索在 stem 输出完全消失”，不能证明嵌入质量
足够或此头在当前预算下能学会。本轮直接检验的是：**冻结现有 stem、固定二元候选、
采用该小型因果评分头和上游默认损失，200 步是否足够建立可用证据**。结果是否定的；
不能将其外推为 NRE／BNRE 原理无效，也不能把完整 N02 的修订调度判为无价值。

### 工程、复现与成本

- 新评分头 40,389 参数；冻结 RAW stem 22,400 参数；原完整 encoder 为 159,687
  参数。实际训练总数为 1200 次新头更新，原 encoder 参数更新为零。完整运行含数据生成、
  特征缓存及开发/留出评估为 15.04 s，进程峰值 RSS 709.36 MiB；六臂训练及阶段快照
  分别约 0.91–1.68 s。该成本不含此前 stem 预训练，也不是完整 N02／VLA 推理时延。
- 独立审计重新生成全部训练、开发及留出 RAW，字节一致；复算 9216 个前缀分数与
  行为判据；从 RAW 重跑每种子每拆分一条完整序列，验证特征缓存。两个方法的初始头
  逐位一致，三个原检查点、生产核心和依赖均未修改。
- 对种子 0 的两个方法从第 100 步保存的真实 AdamW 状态回放到 200，模型和优化器
  都逐位一致，没有超过 200 步或产生新候选。审计第一次在最终 JSON 写出时遇到
  NumPy 整数序列化错误，修正并回归后重跑；两次审计合计 400 次重复验证更新，另有
  smoke 的 4 次更新，与正式训练预算分报。
- `make check` 通过，全库 **368 passed / 4 skipped**。四项 skip 仍为本机缺少真实
  NPZ／starVLA 权重等资产，不涉及本轮合成试验。修正审计序列化后再跑 9 项针对性测试
  与 `make check` 均通过。没有修改既有绝对拟合、局部语义反证或证据计数规则。
