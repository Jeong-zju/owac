# N02：辅助 loss、优化耦合与视觉表示的专项诊断

2026-10-16。用户要求仔细检查日志和代码，确认是否由辅助 loss 设置引起正常光闭环失败。本轮**只诊断，不改生产损失/配置，不启动训练或闭环**。完整检查两臂各1000步日志，并在 RAW900、RGB500、RGB700 三个实际检查点上做12个梯度窗口和视觉激活探针；实际优化更新0。

**结论：当前辅助目标与全局裁剪的组合有可复现的优化耦合问题；更直接的异常是已选权重的视觉表示几乎恒定，以及 RGB 后期动作路径本身严重不稳定。不能把全部失败归为“辅助 loss 公式写错”或仅凭全参数梯度倍数认定它压制共享编码器。辅助目标是否诱发表示坍缩，还需要训练消融，当前没有这项因果证据。**

## 2. 损失计算没有发现的错误，以及真正的设置问题

当前实际目标为 `L_action + 1*L_masked + 1*L_causal`，噪声项关闭。源码核查：

- 动作项沿用后端的32维 flow velocity MSE；控制维为14，其余为填充。不是完整采样动作误差。
- 掩码项为被遮区域的重建误差，共享骨干；RAW和固定ISP后的RGB各自在本臂输入空间监督，数值尺度不自动相同。
- 因果项是高斯 NLL，含平方残差/方差、`log variance` 和常数；使用先前状态/特征预测当前帧，按有效标量数除回平均，再按先前支持权重聚合。**不是忘记除几十万个像素，也没有发现本轮新增的当前图像泄漏或损失符号写反。**
- 连续密度的 NLL 可以为负。负值本身不是 bug，也不能单凭负值判断方差已经塌到下限。它与动作 MSE 相加后的总 loss 不是直观的控制效果分数。

关键设置问题位于 `training/n02_v12.py:1813`：所有参数组、所有目标相加后，一起以 norm=1 裁剪。虽然 AdamW 有独立参数组和学习率，**裁剪比例仍由全部参数共享**。辅助目标仅在解码器上的大梯度，也会缩小动作读出层当前这一步的梯度；已有 Adam 一阶/二阶历史状态不会同时按当前比例重缩放，因此不能说 Adam 会完全抵消这个作用。

两个辅助权重都写1，没有共享层梯度平衡、独立辅助预训练阶段或按参数组隔离裁剪。设置需要修订，但本轮没有凭单点范数直接替用户指定一个“正确lambda”。

## 3. 分模块结果：修正上轮“34倍/252倍”的解释

使用旧r5的14维提示格式显式复现其目标，避免混入r6输入修补；固定四个窗口、batch2、相同噪声/时间与掩码种子，覆盖 grab_roller、一个预定中部窗口、历史675步/360步对应的窗口。三个检查点共12组。后两种窗口使用的是各已保存检查点权重，并非历史尖峰发生前的精确状态。

在 RAW900/RGB500 上：

- 因果项全参数大梯度主要位于**测量解码器**，共享编码器的梯度范数仅约 `1e-8…7e-7`。
- 动作项在共享编码器上约 `1.4e-4…1.0e-2`，在策略读出上约 `0.04…0.58`；对候选/校正器的梯度很小。
- 掩码项会作用于共享编码器，但12组共享编码器动作/掩码余弦范围约−0.144…+0.035，不能概括为持续强烈反向。
- 这12组里，经**当前候选权重q**反传的动作梯度只占总动作梯度范数约 `1e-8…6.4e-5`。因此，虽然全测量求和进入softmax值得保留数值审计，本轮没有复现它是当前权重梯度异常的主要通路。没有擅自改变推理能量定义或截断生产q梯度。

上一轮34倍/252倍是一个窗口的**全参数范数比**，并不是共享编码器上的任务竞争比。应把它解释为“全局裁剪可能被辅助分支控制”的线索，不能据此宣称“辅助项直接压住动作编码器”。

## 4. 读取真实 Adam 状态后，耦合效应可复现

对每个窗口，在同一检查点、同一历史 Adam 状态与学习率下，分别计算假设只保留动作、动作+掩码、动作+因果、全部目标时的**虚拟下一步向量**，包括裁剪、bias correction、epsilon与weight decay。没有调用策略优化器step，也没有将向量写入模型。计算公式以可丢弃的三个数值fixture与真实PyTorch AdamW一步对照，测试通过。

比较 `g_action · delta`，它是动作loss的**一阶变化预测**：

| 检查点 | 全目标/动作单独的一阶下降量比例 | 含义 |
| --- | --- | --- |
| RAW900，4窗口 | 0.343 / 0.0119 / −0.0237 / 0.0815 | 一个窗口由预测下降变为预测上升 |
| RGB500，4窗口 | 0.148 / 0.297 / 0.372 / 0.100 | 下降预测仅保留约10%—37% |
| RGB700，4窗口 | 0.793 / 0.980 / 0.696 / 1.000 | 当前动作梯度本身已很大，辅助耦合作用相对减小 |

动作+掩码与动作单独大体接近；显著差异主要来自因果预测分支引起的全局裁剪比例变化。这是**当前权重和当前历史状态下的局部优化副作用证据**，不是“关掉辅助项重训后会成功”的证据，也不是实际新权重上的loss/闭环测量。历史Adam状态本身来自联合训练，不能当作动作单独训练的完整反事实。

## 5. 更直接的问题：视觉表示与后端适配

RGB500 的视觉输出在四组不同真实输入上：

| 窗口 | token RMS | 相机/位置轴标准差均值 | 相对首窗口 L2 差 |
| --- | ---: | ---: | ---: |
| grab_roller | 25.250 | 0.000093 | 参考 |
| 固定中部窗口 | 25.282 | 0.000124 | 0.1627% |
| 历史675步对应窗口 | 25.262 | 0.000104 | 0.0643% |
| 历史360步对应窗口 | 25.252 | 0.000094 | 0.0075% |

每个输入有768个相机/位置token，但输出几乎重复同一向量；不同窗口的整体余弦相似度至少0.9999995。**这组检查中，视觉表征出现明显坍缩，空间区分几乎消失**。这与“编码器和桥可执行、flow dev可降低”并不矛盾：动作专家同时得到语言、状态与含有真实动作成分的加噪训练输入，代理loss可以在视觉很弱时下降。

不能把“所有位置相似”单独当成任何全局编码器失效的普遍定理；这里同时看到不同真实输入的表示变化极小、视觉敏感性弱及既有闭环失败。四组探针没有覆盖所有观测，也没有证明图像对动作完全无影响。

RGB700在相同四窗口上，视觉空间标准差变为约11.8—13.4，token对动作loss的梯度范数比RGB500约大159—6300倍；完整前端的**动作单项**梯度由0.04—0.58变为10.24—161.49（配对约18—4043倍）。这确认后期读出/后端适配已进入另一种不稳定状态，不能只看辅助loss数值。当前探针不定位是哪一次更新触发转变，也不据此证明head学习率3e-4就是唯一原因。

RAW900也存在同类异常：四窗口 token RMS 为39.61—40.46，位置标准差均值仅0.00165—0.00223，跨窗口余弦至少0.9999927。与此同时，RAW编码器输出的各相机/多尺度特征，在空间轴上的标准差/RMS为0.205—0.501，并非编码器所有空间值都已恒定；读出端该比值降至约 `4e-5…6e-5`。这把异常进一步定位在**完整N02策略读出输出端**，不能只责怪RAW传感器输入或单个视觉骨干。

这些值是近似恒定，不是逐位相同，也不是“图像完全没有任何作用”的证明。当前证据不足以区分Perceiver潜变量聚合、输出投影、联合目标历史与学习率各自对坍缩的贡献。

## 6. 处理顺序与证据边界

优先修订**联合优化配方和视觉表征验收**。先用r6正确状态输入建立动作单独监督的正常光可学对照，监测实际采样动作、跨图像特征变化与位置多样性；再分别加入masked与causal项。对辅助独占分支采用独立裁剪/优化管理；共享编码器按分项梯度和动作目标验证权重，避免仅按loss数值设等权。读出学习率及调度也应进入稳定性对照，而不是把延长原训练当作修复。

动作单独、动作+masked、动作+causal、完整目标的训练消融，才能回答辅助项是否诱发坍缩、是否伤害最终抓取；**本轮未启动这些训练**。目前最准确的结论是：配方有已验证的耦合缺陷，视觉表示有实际异常，辅助目标不是唯一已确证的根因。
