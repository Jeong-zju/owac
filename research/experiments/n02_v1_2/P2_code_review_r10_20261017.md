## 已确认的代码和执行缺口

### P1 分层采样永久丢掉多数演示的开场

位置：[`n02_v12_task.py:81`](../../../src/owac/training/n02_v12_task.py#L81)。`BalancedBlocks` 先按整个 anchor 表每8行切块，再把跨演示的块整个丢弃。演示长度不是8的整倍数时，下一段开头也随前一段末尾一起被丢弃；增加训练步数无法重新抽到它们。块的阶段标签只取第一行，跨 t10 等阶段边界的样本也被算到错误的组。

对实际冻结训练表3668行逐项复算：3630个有效 anchor 中，**231个永远不可达**；其中137个在 t0–9。38段演示中，**33段的 t0 不可达**，Normal 的5段训练演示有4段丢掉 t0。另有237行的真实阶段与所在块标签不一致。上一轮“确定性曝光顺序核验通过”只能证明执行遵循了这个有缺陷的调度，不能证明覆盖正确。

现有测试的两段演示都固定长96帧，恰好能被8整除；它们只检查不跨集、组标签和确定性，没有检查所有有效行最终可达。见 [`test_n02_r9_task.py:16`](../../../tests/test_n02_r9_task.py#L16)。修复应按演示及阶段边界分别分块、保留短块，或显式拼接抽中的 anchor；必须对真实变长演示检查“有效样本无永久遗漏”，并给修改后的采样协议新版本。

证据：[实际索引复算](review_r10_20261017/static_audit.json)、[可复现脚本](review_r10_20261017/static_audit.py)。

### P1 选型指标与实际执行存在两层偏差

位置：[`run.py:24`](task_r9_20261017/run.py#L24)、[`n02_v12_task.py:113`](../../../src/owac/training/n02_v12_task.py#L113)、[`n02_v12_robotwin.py:264`](../../../src/owac/runtime/n02_v12_robotwin.py#L264)。训练对有效未来50步等权；选型的开场保护也看50步，记录的 `first10_mse` 不参与晋级。闭环每10步重规划，实际只执行预测块前10步，因此后40步改善可以掩盖真正执行部分的退化。这并不意味着所有50步训练都错误，而是当前选型缺少与执行对应的保护。

此外，离线误差评估未经限幅的动作，闭环却把关节相对上一条指令的变化限制为0.05rad，夹爪也限制为每条0.05并截到[0,1]。上一轮对照32步的400条指令中，**395条被改写**；请求与执行的12关节 RMS 差0.3618rad、单关节最大差3.8215rad，夹爪最大差0.6178。当前离线分数没有反映这条实际动作序列。

原始 π0.5 的84步成功参照使用50步重规划且没有这条限幅，因而不能作为相同新执行协议下的成功见证。离线把同一限幅作用于已保存的原始84条指令，会改写76条，关节最大差1.2619rad；这只是指令反事实，不是新的机器人轨迹，也不能推断限幅后成功或失败。

修复方向是明确并统一执行协议：至少将前10步、开场关节和夹爪作为独立验收项；对有状态的限幅，验证需要带着真实执行状态滚动进行，不能把离线每个窗口独立裁一下就当闭环。保留完整50步指标用于诊断。先核查原始策略在相同重规划与限幅协议下的行为，再比较新前端。r9任务组目前全部被门槛挡住，不能把此缺口写成该组已被错误晋级。

证据：[执行改写复算](review_r10_20261017/receipts/receipt_probe.json)、[既有 r9 选型](task_r9_20261017/receipts/task/selection.json)。

### P1 校准检查和状态修订尚未接到在线主链

位置：[`n02_v12.py:1384`](../../../src/owac/training/n02_v12.py#L1384)、[`inference_v12.py:713`](../../../src/owac/frameworks/n02_full/inference_v12.py#L713)。`calibration_pass()` 拟合后只返回统计，没有把校准器装入模型，也没有随 checkpoint 保存可恢复的校准对象。运行配置没有校准器，`Policy` 恢复权重后也不重新校准；当前8帧窗口的检查返回 `valid=False`。12组实际诊断中，有效检查为0；开场无因果前缀，t10则无已拟合的在线校准器。

即使提供了校准器，当前 `step()` 也只把 verdict 放进输出：后续读出、提交状态不根据 `model_inadequate` 触发修订。`rebuild()` 是可手动调用的入口，训练 token source 和在线 `Policy` 都没有按检查结果调用它。对应目标可见[方案4.3与5.3](../../../docs/plans/N02_full_development_v1.2.md)。不能把“有重建函数”和“检查函数被调用”当成在线反证修订已经实现。

此外，抽查的12个最终状态都没有接受四轮中的任何修正；三个 t10 窗口各自的8个观测仍实际调用编码器8次、RAW解码器47次、读出8次。不能据这几个窗口判整个候选机制无用，但当前没有正面证据支持其改善了任务表征。固定权重下重新校准并接入有明确规则的修订策略，才具备检验这部分能力的条件；训练中变化的权重不能继续沿用旧阈值。

## 表征和动作目标的设计风险

### 融合恢复了空间变化 但仍没有建立原视觉塔的语义接口

位置：[`representation_v12.py:25`](../../../src/owac/frameworks/n02_full/representation_v12.py#L25)、[`readout_v12.py:804`](../../../src/owac/frameworks/n02_full/readout_v12.py#L804)。当前主空间支路对每张图的每通道减去空间均值，并在投影前后都归一化空间能量，再对每个输出token做 LayerNorm、固定RMS为4。**每张图自己的通道均值也包含图像内容，不能一概视为无用偏置。** 当前设计把这部分信息主要留给另一个较小的上下文支路，而非让网络自行选择全局与局部信息的比例。

相同历史初态的既有收据中，原始视觉塔输出的空间中心化能量占比为3.39%，r8读出为96.45%；RMS分别4.329与4.019。两者总幅度相近，不代表通道含义和空间分布匹配。该差异本身不证明何种分布更优，但在冻结原始后端时，必须通过任务适配证明新接口可用，不能用“有空间差异”替代。

本轮零更新去掉约10%幅度的上下文支路，固定输入下14维动作 RMS 差仍达0.3946–1.3882，留出误差变化也并非全部同向。该现象支持读出与冻结后端对融合方式高度敏感；这是改变模型的反事实，不能当成“去掉N02就成功”的消融结果。后续应允许全局内容与局部细节共同学习，检验各尺度和上下文的任务贡献，同时约束幅度；不应继续仅靠固定归一化比值来定义“好表征”。

既有分布收据：[原视觉塔](visual_gap_20261016/receipts/native.json)、[r8读出](representation_r8_20261016/receipts/selected-frontend-probe.json)。当前干预：[runtime_probe](review_r10_20261017/receipts/runtime_probe.json)。

### P2 只监督14维并不使另18维变成无影响的填充

位置：[`n02_v12.py:1045`](../../../src/owac/training/n02_v12.py#L1045)、[`rawvla_features.py:1395`](../../../src/owac/backends/rawvla_features.py#L1395)。r9丢弃后18维的速度损失，但仍输入、预测、积分完整32维；后18维经过同一个 `action_in_proj` 再进入网络。最后只执行14维，不会切断这些内部维度在前面去噪步骤的影响。固定本轮输入，只重采后18维初始噪声，前14维动作 RMS 差0.0216–0.0731；将后18维约束到零目标的解析路径，差0.0269–0.1162，专家误差没有一致改善。

这是确实存在的耦合风险，不是已确认的首要失败原因；原始模型的32维目标、r9的14维目标也不能再说完全相同。应比较保留原生补齐维度约束与明确隔离这些维度的实现，并单独报告14维控制指标。没有依据直接添加新的抗噪辅助项。

## 已排查但不能当成主因的项目

- 本轮比较了真实LoRA权重下联合训练前向与缓存推理前向。生产BF16路径速度 RMS 差约0.008–0.015；去掉TF32仍有差异。把后端临时转FP32且关闭TF32后，两个实际窗口的完整32维速度**逐位相同，最大差0**。这支持差异来自低精度执行路径，未发现这两个窗口存在缓存掩码或LoRA接线的结构性偏差，不能外推为所有情况的证明。
- 动作噪声固定时，生产采样和诊断重放12/12完全一致，重复生产采样也12/12完全一致。首个探索探针的手写时间步与生产浮点累加不一致，相关反事实结果没有采用；有效证据来自修正后断言逐位一致的 `review-r10-a2`。
- 14→32维状态提示的既有修复仍在，训练和运行时共享 `prepare_language_state`；本轮新发现的是任务文字来源，不是同一旧bug的重新命名。
- 训练与在线RAW的噪声开关、shot/read参数在既有收据中一致。暗光敏感性成立，但只有每档一个固定初态的噪声干预，不能把它换算为闭环失败占比。
- 旧r5训练池身份包含episode0，但传给r7的900步之前优化日志没有命中该轨迹。没有仅凭“在训练池中”就断言实际曝光；当前闭环依然按开发验证管理，不作独立成功率宣称。
